# Authentication Bypass in /api/login endpoint

**ID:** vuln-0001
**Severity:** CRITICAL
**Found:** 2026-09-18 06:07:27 UTC
**Target:** https://example.com/api/login
**Endpoint:** /api/login
**Method:** POST
**CVSS:** 9.8
**Confidence:** High
**Fix Effort:** Low

## Description

The /api/login endpoint allows unauthorized access by bypassing authentication checks, enabling unauthorized user sessions.

## Evidence

Response: {"status": "success", "session_token": "abc123"}

## Impact

An attacker can gain access to user accounts and perform actions on behalf of authenticated users.

## Counterevidence

No authentication checks were found in the endpoint's code, but the vulnerability was confirmed via PoC.

## What Would Change This Severity

If the endpoint is accessible over HTTPS with no encryption, the severity would decrease.

## Technical Analysis

The /api/login endpoint lacks proper authentication validation, allowing attackers to send crafted requests without valid credentials.

## Proof of Concept

1. Send a POST request to /api/login with empty credentials.
2. Observe the response grants access without authentication.

```python
curl -X POST https://example.com/api/login -H 'Content-Type: application/json' -d '{"username": "", "password": ""}'
```

## Remediation

Implement proper authentication validation in the /api/login endpoint. Use middleware to enforce session tokens and validate credentials before granting access.

## Assumptions

Assumes the attacker can send unauthenticated requests to the /api/login endpoint.
